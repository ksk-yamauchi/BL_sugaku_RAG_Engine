# 🏛️ システムアーキテクチャ & オントロジー構造

本ドキュメントでは、スタサプRAGエンジンのシステム全体の構成、および「GNN-KT（知識追跡）」と「オントロジー（見方・考え方）」を両立させた次世代のメタデータモデルと、それを体現するベクトルデータベースの設計思想について解説します。

---

## 🌟 1. 進化の軌跡と設計思想（パラダイムシフト）

本アーキテクチャは、これまでの「解けるか・解けないか（技能偏重）」のAIから、「生徒がどう思考し、どう視点を切り替えたか（数学的な見方・考え方）」をシステム上で計算・追跡可能にするという、教育AIにおける革命的なパラダイムシフトを体現しています。

### 課題：意味的なすれ違いの発生
従来のシステムは、GNN-KTの確率計算に最適化するため、概念をすべて「〜を特定する」といった【技能（動詞）】として抽出していました。しかし、学校のシラバスは「単項式」「係数」といった【知識（名詞）】で書かれているため、ここで意味的なすれ違い（歯抜け）が発生し、精緻なマッチングができない状態でした。

### 解決：「三つの柱」に基づく知識と技能の完全分離と「知識群」の動的再構成
文科省の「三つの柱」を掛け合わせ、「知識（名詞）」と「技能（動詞）」を厳格に分離し、それらを意味のあるエッジ（線）で結ぶ【デュアルエンジン設計】へと進化しました。

ここで抽出される**「知識群（Knowledge Cluster）」は、固定化されたパッケージではなく、目的とする技能や適用される視点によって動的に再構成される「網の目」としてシステム上に表現されます。**

さらに、数学における証明の機能（検証だけでなく、**説明、発見、体系化**が重要であるという De Villiers の理論）に基づき、単なる「タスクの結果を名詞化しただけの知識」の抽出を禁止しました。
その代わり、「ある文字に着目する」といった【視点・条件（レンズ）】を通すことで、「定数項＝数字」という固定観念が壊れ、「着目文字を含まないブロック」へと知識が【再構成】されるプロセス（ゲシュタルトの変換）のみを抽出しモデル化しました。

これにより、ナレッジグラフは単なる用語辞典から、生徒が「なぜそのように解くのか（説明・パラダイムシフト）」を表現し、知識がどう変容し（発見）、タスク解決という体系の中にどう位置づけられるか（体系化）を示す動的なネットワークへと進化しました。

### 💡 【背景と未来構想】「知識群」による真の概念理解のモデリング
この「知識群」という概念の導入には、**「部分の足し算」ではない、真の「概念理解」をシステム上でモデリングする**という明確な教育的意図と、次世代機能への拡張構想が含まれています。

*   **体系的な理解の表現**: 生徒が「単項式の係数」と「単項式の次数」を個別に知っていることと、「単項式の基盤という知識群全体を体系として理解している」ことは全く異なります。基礎的な知識群が上位の概念（整式の定義など）へ統合され、さらに【思考力・判断力】のフィルターを通ることで新たな「再構成された概念（知識群）」へと変容していく動的なプロセスを、システムアーキテクチャとして直接表現しています。
*   **GNN-KTとSemantic Zoomの進化**: 今後の開発において、個々のタスクノードの正答率を追跡するにとどまらず、「単元（ハブ概念）」×「三つの柱（知識/技能/思考・判断）」の掛け合わせである『知識群』という面で習熟度を捉えます。これにより、「この生徒は単純な計算（技能群）は定着しているが、文字を定数とみなすような数学的な見方（再構成の群）に弱点がある」といった、**現場の先生が持つ「高度で直感的な見立て」をAIで精緻に可視化・再現する**ための強力な基盤となります。

## 🧠 2. 新オントロジーモデル：4つのノード（頂点）

ナレッジグラフを構成するノードは、計算対象（動詞）と解釈対象（名詞）を明確に分けるため、以下の4つの型に厳密に分類されます。システム（DB）上では、これらが文科省の「三つの柱（Pillar）」および「役割（Role）」としてメタデータに直接刻み込まれます。

| ノード種別 / 属性 | 意味と役割 (Role) | 三つの柱 (Pillar) |
| :--- | :--- | :--- |
| **foundation_knowledge**<br>(基礎知識 / 名詞) | 「単項式」「係数」など、条件によって揺らがない純粋な数学的定義や用語。数学の「体系化」の土台であり、シラバス検索の強力な受け皿（辞書）となります。 | **知識及び技能** |
| **perspective_condition**<br>(視点・条件 / レンズ) | 「ある文字に着目する」など、生徒に視点の切り替えを要求するルールや条件。基礎知識を相対化させ、事象の本質を捉え直す「レンズ」として機能します。 | **思考力，判断力，表現力等** |
| **derived_knowledge**<br>(再構成された知識) | 「基礎知識」に「視点・条件」を通した結果、新しく変容した高度な知識（例：「定数としての文字の扱い」）。単なる結果論ではなく、真の気付き（パラダイムシフト）を表現します。 | 思考の変容プロセス |
| **tasks**<br>(技能・タスク / 動詞) | 生徒が知識を用いて実際に行う計算手順や操作アクション。動画や問題が直接紐付く「ゴール地点」であり、**GNN-KTの確率計算の主役**となります。 | **技能** |

> 💡 **【次世代構想】タスクの構造的難易度と重み付け**
> GNN-KTの推論において、前提知識（`prerequisite`）に「再構成知識」を挟むタスクは、視点の切り替え（ゲシュタルトの変換）という高い認知負荷を伴うため「高度な技能（高難易度）」として重み付けされます。（※アルゴリズムの詳細は `09_next_gen_ux_and_algorithm.md` を参照）

## 🔗 3. 新オントロジーモデル：9つのエッジ（思考の軌跡）

ノード同士を結ぶエッジは、単なる線ではなく生徒の「思考と活動の軌跡」そのものを表します。DB上では、これらがGraph RAGでの高速な推論を可能にするため、関係性ごとに構造化されて格納されます。

1. **`part_of` (構成要素)**: ある知識が別の知識の一部である関係。（例：「係数」は「単項式」の構成要素）
2. **`is_a` (特殊例・分類)**: ある知識が別の知識の特殊な状態である関係。（例：「定数項」は「単項式」の特殊例）
3. **`subsumes` (包摂・統合)**: 上位概念が下位概念を包み込む関係。（例：「整式」が「単項式・多項式」を統合する）
4. **`relative_to` (相対化される)**: 基礎知識が「視点・条件ノード」によって意味を変えられる関係。（思考のジャンプを測定する指標）
5. **`applies_condition` (条件の適用)**: 視点・条件から、再構成された知識へと向かう推論のプロセス。
6. **`requires_logical` (論理的判断の要求)**: 再構成された知識を用いて、高度な技能（タスク）を実行する関係。（単なる暗記ではなく、演繹的推論を求めていることを示す）
7. **`applied_to` (単純適用)**: 基礎知識をそのまま用いて、基本的な技能（タスク）を実行する関係。
8. **`explanation` (理由・説明)**: 例外やルールの論理的な理由付け。（例：「0の扱い」から「次数」への線。コミュニケーションと説明機能を担う）
9. **`prerequisite` (前提知識)**: 技能や知識を学ぶために不可欠、あるいは補足となる過去の知識。（遡り学習のルート）

## 🗄️ 4. 新世代ベクトルDBの設計思想（Embedding & Metadata）

上記の「教育的オントロジーの魂」を検索エンジン（RAG）に直結させるため、グローバルベクトルDB（`global_vector_db_cache.json`）の構築プロセスにおいて、ノードの型に応じた高度なメタデータ付与とベクトル化（Embedding）のレシピ分岐を行っています。

### ① 役割（Role）に応じたベクトル生成レシピの分岐
AIがノードの意味を正しく空間配置できるよう、合成テキスト（プロンプト）の味付けを意図的に変えています。
*   **知識ノード群 (`_K` 系)**:
    「三つの柱」や「役割」をテキストの冒頭に刻み込むことで、「〜とは何か」「どう見ればいいか」という意図の検索にダイレクトにヒットさせます。さらに `mext_master_dict.v2.json` から文科省の公式テキストを引き込み、メイン動画・復習用動画の「概念講義の要約」を濃くブレンドします。

*   **タスクノード (`_T` 系)**:
    「技能」としての役割を明記し、アライメント情報から**「実際に紐づいている具体的な問題文と解説」および「動画の板書OCR（数式）」を裏側で結合**してベクトル化します。これにより、生徒が具体的な数式（例：「$2x^2+3x+1$」）で画像検索した際、概念ではなく「このタスクだ」とダイレクトにヒットするようになります。

### ② エンティティ統合とオートワイヤリング（自動エッジ結線）
AIの抽出揺らぎによる「階層の逆転」や「孤立ノード」を防ぐため、DB構築時に**オートワイヤリング機能**が働きます。子ノードの `parent_concept` が既存ノードと一致した場合、システムが自動的に `subsumes`（親➔子）および `part_of`（子➔親）のエッジを強制的に結線し、強固なGraph RAGネットワークを自動生成します。

## 🗂️ 5. マスターデータの分割管理と「記憶の継承」

デュアルエンジン設計をシステム上で安定稼働させるため、マスター辞書を「動詞用」と「名詞用」に分割して管理します。

   **知識マスター (`knowledge_master.json`)**: 用語のブレを防ぎ、日本の高校数学（検定教科書レベル）の標準的な名称にグラウンディングされた概念（名詞）を蓄積します。
   **タスクマスター (`task_master.json`)**: 「単項式の係数を特定する」「多項式の定数項を特定する」といったように、行う操作が似ていても対象が異なる場合は、GNN-KTで別々の技能として追跡するために独立した枝番（`_Txxx`）として管理されます。

### 🧠 記憶の継承 (Ontology Memory Injection)
単元ごと（PARTごと）にAIが独立して解析を行うと「特定の文字に着目する」と「特定の文字への着目」のような表記揺れ（エンティティの分裂）が発生します。
これを防ぐため、Phase 1 の抽出時に**過去にマスターに登録された概念名リストをプロンプトにインジェクト（注入）**し、AIに「既存の用語と同一なら一言一句同じ名称を使い回す」という絶対ルールを課しています。これにより、全カリキュラムを通じてオントロジーが美しく1つのツリーに収束します。

## 🌐 6. 動的オントロジー補完と主従分離アライメント (Phase 3)

本アーキテクチャは、テキスト教材に依存するだけでなく、講義動画からマルチモーダルに学習ネットワークを拡張（自己増殖）できる点に特徴があります。

*   **暗黙知の動的追加 (Dynamic Ontology)**:
    動画の口頭解説や板書OCRから、テキストには書かれていない『暗黙の知識』や『新しい視点』をAIが発見した場合、知識ノードとして自動補完されます。
*   **動画アライメントの主従分離**:
    動画をノードに紐づける際、AIが動画での扱われ方の深さを判定します。その概念を初めて導入するメイン教材であれば `main_videos` に、別の問題を解くための前提知識としての復習であれば `review_videos` に厳密に分離してDBに格納し、フロントエンドでの意味のある出し分けを実現します。
*   **動画ロール連動による「粒度吸収」**:
    動画がUI用に極細分割されている場合でも、AIが動画の `role`（`exercise_walkthrough` 等）を判定し、既存のタスクノード内に「一連のプロセス（配列）」として束ねて紐付け、粒度のズレを美しく吸収します。
