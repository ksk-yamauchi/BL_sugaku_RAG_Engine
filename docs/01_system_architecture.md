# 🏛️ システムアーキテクチャ & オントロジー構造

本ドキュメントでは、スタサプRAGエンジンのシステム全体の構成、および「GNN-KT（知識追跡）」と「オントロジー（見方・考え方）」を両立させた次世代のメタデータモデルについて解説します。

---

## 🌟 1. 進化の軌跡と設計思想（パラダイムシフト）

本アーキテクチャは、これまでの「解けるか・解けないか（技能偏重）」のAIから、「生徒がどう思考し、どう視点を切り替えたか（数学的な見方・考え方）」をシステム上で計算・追跡可能にするという、教育AIにおける革命的なパラダイムシフトを体現しています。

### 課題：意味的なすれ違いの発生
従来のシステムは、GNN-KTの確率計算に最適化するため、概念をすべて「〜を特定する」といった【技能（動詞）】として抽出していました。しかし、学校のシラバスは「単項式」「係数」といった【知識（名詞）】で書かれているため、ここで意味的なすれ違い（歯抜け）が発生し、精緻なマッチングができない状態でした。

### 解決：「三つの柱」に基づく知識と技能の完全分離
De Villiersの論文が示す数学の機能（体系化・説明・発見）と、文科省の「三つの柱」を掛け合わせ、「知識（名詞）」と「技能（動詞）」を厳格に分離し、それらを意味のあるエッジ（線）で結ぶ【デュアルエンジン設計】へと進化しました。

### 「見方・考え方」のネットワーク化
「ある文字に着目する」といった【視点・条件（レンズ）】を通すことで、「定数項＝数字」という固定観念が壊れ、「着目文字を含まないブロック」へと知識が【再構成】されるプロセスを図解・モデル化しました。これにより、ナレッジグラフは単なる用語辞典から、生徒の思考力やパラダイムシフトを表現できる動的なネットワークへと進化しました。

## 🧠 2. 新オントロジーモデル：4つのノード（頂点）

ナレッジグラフを構成するノードは、計算対象（動詞）と解釈対象（名詞）を明確に分けるため、以下の4つの型に厳密に分類されます。

| ノード種別 / 属性 | 意味と役割 | 三つの柱との関連 |
| :--- | :--- | :--- |
| **foundation_knowledge**<br>(基礎知識 / 名詞) | 「単項式」「係数」など、条件によって揺らがない純粋な定義や用語。数学の「体系化」の土台であり、シラバス検索の強力な受け皿となります。 | 主に「**知識及び技能**」に紐付く |
| **perspective_condition**<br>(視点・条件 / レンズ) | 「ある文字に着目する」など、生徒に視点の切り替えを要求するルール。基礎知識を相対化させるレンズとして機能します。 | 主に「**思考力，判断力，表現力等**」に紐付く |
| **derived_knowledge**<br>(再構成された知識) | 基礎知識に「視点・条件」を通した結果、新しく変容した高度な知識（例：「特定文字に着目した定数項」）。新たな気付き（パラダイムシフト）を表現します。 | 思考の変容プロセス |
| **tasks**<br>(技能・タスク / 動詞) | 生徒が知識を用いて実際に行う計算手順や操作アクション。動画や問題が直接紐付くゴール地点であり、**GNN-KTの確率計算の主役**となります。 | 知識を活用した「**技能**」 |

## 🔗 3. 新オントロジーモデル：9つのエッジ（関係性）

ノード同士を結ぶエッジは、生徒の「思考と活動の軌跡」そのものを表します。この緻密なエッジ構造により、GNN-KTによる適応型学習が可能になります。

1. **`part_of` (構成要素)**: ある知識が別の知識の一部である関係。（例：「係数」は「単項式」の構成要素）
2. **`is_a` (特殊例・分類)**: ある知識が別の知識の特殊な状態である関係。（例：「定数項」は「単項式」の特殊例）
3. **`subsumes` (包摂・統合)**: 上位概念が下位概念を包み込む関係。（例：「整式」が「単項式・多項式」を統合する）
4. **`relative_to` (相対化される)**: 基礎知識が「視点・条件ノード」によって意味を変えられる関係。（思考のジャンプを測定する指標）
5. **`applies_condition` (条件の適用)**: 視点・条件から、再構成された知識へと向かう推論のプロセス。
6. **`requires_logical` (論理的判断の要求)**: 再構成された知識を用いて、高度な技能（タスク）を実行する関係。（暗記ではなく演繹的推論を求めていることを示す）
7. **`applied_to` (単純適用)**: 基礎知識をそのまま用いて、基本的な技能（タスク）を実行する関係。
8. **`explanation` (理由・説明)**: 例外やルールの論理的な理由付け。（例：「0の扱い」から「次数」への線。コミュニケーションと説明機能を担う）
9. **`prerequisite` (前提知識)**: 技能や知識を学ぶために不可欠、あるいは補足となる過去の知識。（遡り学習のルート）

## 🗂️ 4. マスターデータの分割管理

デュアルエンジン設計をシステム上で安定稼働させるため、マスター辞書を「動詞用」と「名詞用」に分割して管理します。

*   **知識マスター (`knowledge_master.json`)**: 用語のブレを防ぎ、日本の高校数学（検定教科書レベル）の標準的な名称にグラウンディングされた概念（名詞）を蓄積します。
*   **タスクマスター (`task_master.json`)**: 「単項式の係数を特定する」「多項式の定数項を特定する」といったように、行う操作が似ていても対象が異なる場合は、GNN-KTで別々の技能として追跡するために独立した枝番（`_Txxx`）として管理されます。

## 🌐 5. 動的オントロジー補完と粒度吸収アライメント (Phase 3)

本アーキテクチャは、テキスト教材に依存するだけでなく、講義動画からマルチモーダルに学習ネットワークを拡張（自己増殖）できる点に特徴があります。

*   **暗黙知の動的追加 (Dynamic Ontology)**:
    動画の口頭解説や板書OCRから、テキストには書かれていない『暗黙の知識』や『新しい視点（例外ルールなど）』をAIが発見した場合、知識ノード（`_Kxxx`）として自動補完されます。*(※GNN-KTモデル保護のため、動画からのタスク`_Txxx`の新規追加は禁止)*
*   **動画ロール連動による「粒度吸収」**:
    動画がUI用に極細分割されている場合でも、AIが動画の `role`（`exercise_walkthrough` 等）を判定し、既存のタスクノード内に「一連のプロセス（配列）」として束ねて紐付け、粒度のズレを美しく吸収します。
