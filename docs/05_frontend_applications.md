# 📱 フロントエンドアプリケーション（UI）詳細仕様

本ドキュメントでは、スタサプRAGエンジンのフロントエンドディレクトリ（`BL_sugaku_I_Frontend/`）に配置されている、生徒向け・教員向けアプリケーションの詳細な仕様とUI/UXの設計思想について解説します。

---

## 🎓 1. 生徒向け AIチューター (`app.py`)

構築済みのベクトルデータベース（`global_vector_db_cache.json`）を読み込み、生徒に対して直感的かつ高度な学習体験を提供するStreamlitベースの対話型UIです。サイドバーには現在読み込んでいるDBのバージョン（`engine_version`）が動的に表示されます。

### 1.1 マルチモーダル検索 ＆ 厳格なJSON意図判定（画像検索）
* スマホ等で撮影したノートやプリントの画像をアップロードして検索が可能。
* 裏側でGemini Visionが画像を解析し、厳格なJSON形式で抽出・パースを実行。単なる文字起こしではなく、スタサプの4階層オントロジーに直結する以下のメタデータを推論・抽出します。
  * **`inferred_parent_concept`**: 抽出した問題からLevel 3（親概念ハブ）を推論し、Lexical Boost（完全一致加点）による高精度な動画検索を実現。
  * **`missing_prerequisite`**: 生徒の解答プロセスから「躓きの根本原因（不足している前提知識）」を推論し、Graph RAGと連動して遡り学習用の復習動画をセットでサジェスト。
  * **`error_type` / `error_analysis`**: 計算ミスか概念未理解かを分類し、具体的なエラー箇所を特定。
  * **`suggested_hint`**: いきなり答えを教えるのではなく、生徒の自律的学習を促すための「気づき」を与えるティーチングヒントを生成。
* **【リード文結合機能】** 「次の式を展開せよ。」のような共通の指示文を自動検知し、各小問の冒頭に結合してベクトル検索の精度を劇的に向上。
* **【ゼロ・レイテンシのノイズ除去】** 画像から抽出されたテキストに含まれる「小問番号」や「LaTeX数式」を、LLMを介さず正規表現（Regex）で瞬時に自動サニタイズ。UX（応答速度）を損なうことなく、検索の誤爆を完全に防止。
* 複数問が検出された場合は、整形された問題の選択ボタンを動的に生成し、ユーザーに解きたい問題を1つ選ばせるUIへスムーズに移行。

### 1.2 ハイブリッド・スマートルーティングと条件付きHyDE
* **【条件付きHyDEによる精度向上】** 数式記号を含む検索や画像検索時に自動でLLMを発動。数学的な解法アプローチを事前推論して検索クエリに合体させ、純粋なベクトル検索では到達できない高精度なタスク・マッチングを実現します。
* **【ID指定ワープによる確実な遷移】** UI上のボタン遷移において、テキスト再検索によるベクトルのブレを排除。`ID` を指定して絶対的な単独トップヒット遷移を行い、ノイズのない確実なドリルダウンを提供します。
* **【教育的セーフティネット】** ノードが持つ `global_timeline_index` を比較し、検索トップより「未来（未習）」の範囲にある問題や概念に動的にペナルティ（時系列減点）を与え、推奨順位を適正化。

### 1.3 オントロジーと連動したUIの再定義と配列対応
バックエンドにおける「大問（モデリング）と確認問題（アセスメント）の分離」、および「タスク・知識配列の保持（Array Ready）」というオントロジー構造を、UIの画面構成に直接マッピングしています。Ver 4.18.0より、すべての検索の起点を「タスク・概念ノード」に一元化しました。

*   **① 「概念インプット優先ルート」の王道学習体験**
    *   **第一アクション（インプット）:** その概念をゼロから教えてくれる純粋な解説動画。
    *   **第二アクション（モデリング）:** 多段・配列引き当てにより抽出された「大問（`exercises`）」の実物とその解説動画を提示。（※ここから問題ルートへ飛ぶ「詳しく見る」ボタンは、動画のチャプターボタンと機能的役割が重複するためUI上から削除しています）
    *   **第三アクション（アセスメント）:** その概念の理解度を測るための「確認問題（`questions`）」の提示。
    *   **【概念ルートの純化（ノイズ排除）】** ヒットした概念が「タスク」だった場合、他のタスク（応用要素）が混ざった問題をモデリングやアセスメントの候補から完全に排除。初学者が純粋な基礎問題だけに集中できるUXを実現しています（※再構成知識から派生したタスクの場合は例外として許容）。
    *   **【次点リスト（前提）の純化】**: UI上の前提概念リストから、抽象的な「再構成知識」や「視点・条件」を除外し、純粋な基礎知識やタスクのみを提示することで、生徒が遡るべきアクションを明確化します。

*   **② 「問題・解法ステップ優先ルート」とレゴブロック型スキャッフォールディング**
    *   **AIアプローチ解説 (チャットUI):** HyDEによって裏側で生成された「なぜその解法や概念が必要なのか」というLLMの論理的な推論結果を、検索結果の最上部にAIチューターからのメッセージとして美しく表示します。
    *   **本命問題の特定 (2段階ソート＆純化):** 検索の起点となった「タスク」を測る問題群から、検索クエリと最もベクトル類似度が高い問題を「本命」として自動ソート。さらに概念ルート共通の「純化フィルター」を適用し、他タスクが混入した応用問題を本命から排除します。
    *   **解答・解説のアコーディオン:** 本命やモデリング問題の直下に、「解答」と「解説」をスマートに分割表示するエクスパンダーを配置。自律的な自己解決サイクルを促します。
    *   **第一アクション（解法モデリング）:** 本命タスクを測る「大問」の実物とその解説動画を表示。
    *   **第二アクション（概念インプット講義）:** 問題の解法を見た後に、そもそもそのタスクをどう行うかの「概念インプット解説動画」を復習として提示。
    *   **次点（前提確認のアセスメント）:** 本命タスクの「入ってくる矢印（`prerequisite`）」をGNNで逆引きし、真の前提タスク・知識を特定。それを測る確認問題を抽出して表示します。
    *   **【次点問題の超・厳格フィルター】**: 前提問題を引き当てる際、「再構成知識が前提に含まれる問題」や「複数タスクが混在する問題」を徹底排除し、さらに「画面に出現済みの問題」も重複排除することで、完璧に純化された遡り学習を実現します。

*   **③ 主従動画の視覚的出し分けとLaTeXレンダリング**
    *   `concept_introduction`（メイン教材）と `prerequisite_review`（前提・復習）を、UI上でバッジをつけて出し分けます。
    *   先生の「なぜこの動画？」という解説意図のテキストに数式（`$x+y=A$`）が含まれる場合、コードブロックとして扱わず、美しいLaTeX数式としてレンダリングするよう調整されています。
    *   **【Markdown改行パッチ】**: 数式ブロック（`$$...$$`）や多重エスケープを正規表現で保護しつつ、Markdown仕様に合わせた改行（行末スペース2つ付与）を安全に実行し、レイアウト崩れを防ぎます。

### 1.4 問題中心のGraph RAG ＆ 動画チャプターUI
*   **① 問題中心のGNN-KTスキルツリー**
    問題ルートに入った際、本命の問題自身を「📍現在地」として中心に据え、そこから「⬛ 測られるタスク（技能）」と「🟦 必要な知識」へ向かって矢印（エッジ）が伸びるインタラクティブなツリーを描画します。トリガーとなった再構成知識を強調し、周辺情報をトーンダウンすることで、生徒が注目すべきクリティカルパスを視覚化しています。
*   **② リッチな2カラム動画プレイヤー**
    動画の「チャプター」ボタンを押下すると、画面がクリーンな2カラム構成に切り替わります。左側に大きな動画プレイヤーを配置し、右側に解説要約付きの「タイムライン・チャプターリスト」を展開。動画を視聴しながら、ワンクリックで見たいチャプターへダイレクトにジャンプできるモダンな学習UIを提供します。

### 1.5 シームレスな画面遷移と状態管理（UX）
* `st.session_state.history` を用いた履歴管理により、何度深掘り（ID指定ワープ）しても前の検索結果や画像選択画面に正確に後退可能。
* 戻った際に検索窓のテキスト入力内容も復元される親切設計。
* 検索上部のテーマ表示から `(ID:...)` などの内部的なシステムノイズを正規表現で隠蔽し、ユーザーにはクリーンな検索キーワードのみを提示します。

## 🏫 2. 教員向け Semantic Zoom ダッシュボード (`app_ft.py`)

GNN-KTによる推論スコアを活用し、教員が「クラスの躓き」をマクロからミクロまで自在に分析・対応できるダッシュボードUI（プロトタイプ）です。教育現場に即し、評価指標の名称は「習熟度」で統一しています。

### 2.1 階層型ヒートマップ（Treemap）による可視化
* `plotly` の Treemap を用い、「数学Ⅰ・A」等の横断的な大項目から、Level 4の「学習アクション（躓きポイント）」までクリックで自在にズームイン（ドリルダウン）可能。
* 習熟度に応じて、赤（危険）➔ 黄（注意）➔ 青（良好）のグラデーションで色が塗られ、明日の授業でフォローすべきポイントが直感的に判別可能。
* **【ディレイ付きホバー表示】** ブロックにカーソルを合わせると、少しの遅延（ディレイ）の後に習熟度や観点タグがフワッと表示されるUI設計を採用し、画面のチラつき（ノイズ）を防止。

### 2.2 柔軟なフィルタリングと動的アラート
* サイドバーにて、「学年全体」「クラス」のスコープ切り替えが可能。選択した対象に応じて、AI分析レポートの主語が動的に変化します。
* 科目を複数選択（「数学Ⅰ」と「数学A」など）することで、科目を跨いだオントロジーの弱点を横断的に分析可能。
* **面談ダッシュボード（連携機能）**: 担任が面談時に利用するユースケースを想定。AIの科目横断的な傾向分析（青いアラート）を確認し、専門外であっても適切な数学の課題を直接配信できる導線を実装。

### 2.3 既存の「宿題配信」へのシームレスな統合（スマート・ルーティング）
* **学習アクション・エクスプローラー**: ヒートマップ直下に配置された展開パネルから、任意の概念の動画や類題を直接配信可能。**ヒートマップ上でLevel 4のブロックをクリックすると自動的にこのパネルが開き（すでに開いている場合は内容が即座に更新され）、対象のアクションに対する配信設定へスムーズに移行**します。
* **AI分析レポートからのショートカット**: 「見逃せない弱点」と「計算間違い」等の根本原因をAIが指摘し、ワンクリックで「遡り学習パック」の配信設定へ誘導。
* **STEP2 配信設定の自動化**:
  * 配信ボタンを押すと既存の「STEP2: 配信設定」画面（モック）へ遷移。
  * 当該アクションの習熟度が閾値（例: 50%）以下の生徒を**自動で絞り込み**設定。
  * 「動画＋確認テスト」「確認テストのみ」等の宿題タイプを制約に従って**自動選択**。
  * パック配信時は、現在の躓き解説動画と前提知識の復習動画がセットで提示され、先生が中身を確認して不要なものを「×」で個別削除できる柔軟なUIを提供。

### 2.4 マルチモーダル画像RAG（自作プリント・手書き答案解析）
* **手書き答案の一次添削**: 生徒の答案画像をアップロードすると、Gemini Visionが `error_type`（概念未理解か計算ミスか）や `error_analysis` を解析し、Semantic Zoomダッシュボードのクラス傾向分析にデータを供給します。
* **自作プリントマッチング**: 先生の自作プリントから `inferred_parent_concept` や `search_keywords` を高精度にパースし、100%信頼できる公式の類題や解説動画をワンクリックでサジェスト・配信可能にします。
