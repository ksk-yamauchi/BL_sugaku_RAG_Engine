# 🔄 RAG化をベースとした次世代機能構想 (FT & Learn同時)

## 🔄 A. 同時開発によるメリットが絶大な機能ペア（シナジー型）
バックエンドの技術やデータが完全に連動するため、セットで開発することで「開発工数の削減」と「提供価値の倍増」が同時に起きる組み合わせです。

**ペア1：【技術の共有】画像認識RAGエンジン**
*   **対象**: FT 3. マルチモーダル添削 × Learn 1. マルチモーダルAIチューター
*   **同時開発のメリット**: どちらも「ユーザーがアップロードした手書き画像をGemini Visionで解析し、既存のベクトルDBと照合して解説・動画秒数を引き出す」という全く同じバックエンド技術を使用します。UIを作り分けるだけで両方の機能が完成するため、投資対効果が最も高くなります。現在、専用プロンプトの設計まで完了しています。

**ペア2：【データの循環】GNN-KTによるデータ駆動型エコシステム**
*   **対象**: FT 1. 習熟度の可視化 × Learn 2. 適応型学習ナビ
*   **同時開発のメリット**: 生徒がLearnで解く ➔ GNN-KTが真の理解度を推論しFTのダッシュボード（Semantic Zoom）に貯まる ➔ 先生がFTから最適な課題を配信する ➔ Learnの「今日のミッション」に反映される、という教育の高度なPDCAサイクル（データのループ）が完成し、プラットフォームの価値が爆発的に高まります。

## 🚀 B. 独自開発でスピード感・価値提供が高い機能（スタンドアロン型）
他機能とのデータ連携を待たずに単独で切り出せ、現場へのインパクトが大きい（クイックウィンを狙える）機能です。

**候補1：FT 2. シラバス・マッチング（最速・最高コスパ）**
*   **独自の価値とスピード**: 生徒側のログやUI開発を一切必要とせず、既存の「RAG検索エンジン」にシラバスをバッチ処理で流し込むだけで完成します（対話型検証CLIツールが実装済）。
*   **戦略的意義**: 最初の目玉機能としてリリースし、現場から「授業準備がゼロになる！」という絶大な信頼（バイイン）を獲得するのに最適です。

**候補2：Learn 3. スキルツリー可視化（UI特化・高エンゲージメント）**
*   **独自の価値とスピード**: Obsidianのグラフデータ構造をフロントエンドのUIに落とし込む開発が主軸となり、FT側に依存しません（`app.py` にてベース描画実装済）。
*   **戦略的意義**: 学習画面を「自分の成長が開拓されていくマップ」に変えることで、生徒の継続率（リテンション）向上に単独で貢献します。

## 🛡️ C社等の競合に対する優位性（カウンター戦略）

他社の「Graph RAG＋類題生成AI」アプローチに対し、我々はスタサプの独自資産を活かして以下のアプローチで勝ち切ります。

1.  **生成AIに頼らない「公式類題」の確実性**: LLMによる問題生成は数式エラーや指導要領逸脱（ハルシネーション）のリスクを伴います。我々はプロ講師陣が作成した「100%信頼できるスタサプ公式の類題」を、解説動画付きで直接引き出して提示します。
2.  **マルチモーダル ＋ 動画へのダイレクト誘導**: 先生の自作プリントや生徒の手書きノート画像から、数理概念を特定し「解説動画のピンポイントな秒数」へ直接誘導する体験は、他社が容易に追随できない強力な独自価値（Moat）です。
3.  **GNN-KTによる学習状態の動的モデリング**: 他社が単なる「タグ付けと正答率」でレコメンドを行う中、我々は4階層の学習オントロジー（観点タグと重み付き前提関係）を利用したKT（Knowledge Tracing）を実装します。「前提知識の抜け」をネットワーク全体で推論する力は、静的なDBしか持たない他社には模倣できない強力なMoatとなります。
