# 🔍 AIチューター検索エンジンの仕組み (`app.py`)

本ドキュメントでは、フロントエンドアプリ（`app.py`）で採用されている検索アルゴリズム、ハイブリッド検索、スコアリング、およびGraph RAGを用いたネットワーク探索の仕組みについて解説します。

---

## 🌟 主な機能と特徴

### 1. インテント・ルーターと条件付きHyDE (Query Routing)
ベクトル検索が持つ「数式の数学的構造（置き換え等）を理解できない」という弱点を克服しつつ、レスポンス速度を保つためのスマートな振り分け機構です。
*   **高速モード**: 「〜について教えて」など数式記号を含まない純粋なテキスト検索の場合、LLM APIを介さずゼロ・レイテンシでベクトル検索を実行します。
*   **高精度モード (条件付きHyDE)**: クエリに数式記号（`$`, `^` 等）が含まれる場合や画像検索の場合、自動的にLLMを発動させます。「これは3項の平方だから塊に置き換える手法だ」という**AIの事前解説を生成し、検索ワードに合体（Hypothetical Document Embeddings）**させることで、抽象的な解法タスクへ極めて高い精度で着地させます。

### 2. ID指定ダイレクト・ルーティング（排他ワープ）
UI上の「解き方を見る」ボタンや、Graph RAG上のノードをクリックして深掘りする際、再度テキスト検索を行うと類似する別問題へベクトルがブレる（誤爆する）現象を防ぎます。
内部的に `(ID:xxxx)` という識別子を渡し、ベクトル検索やスコア計算をバイパスして、**指定されたノードを「唯一無二のトップヒット」として強制的に確定**させます。これにより、他のルートへのノイズ流出を完全に防ぎます。

### 3. タスク起点の一元化検索と2段階ソート (Array Ready対応)
Ver 4.18.0より、問題解法ルートであっても「問題文テキストへの直接ヒット」を廃止し、すべての検索の起点を「タスク・概念ノード」に一元化しました。
*   **多段・配列引き当て**: 検索によってトップヒットした「タスク（技能）」を起点とし、問題データが保持する「タスク配列（`linked_task_names`）」を参照して、関連する大問・確認問題をすべて引き当てます。
*   **2段階ソート**: 引き当てた複数問題に対し、「ユーザーの検索クエリベクトル」とのコサイン類似度を再計算（2段階ソート）することで、数式検索された内容に最も近い問題を「本命問題」としてピンポイントで抽出し、残りをラジオボタンの候補として整理します。

### 4. Graph RAG による多次元学習ネットワークの構築
トップヒットした概念や問題を中心に、ベクトル検索だけでは拾いきれない**「文脈の繋がり」**を提示します。

*   **概念ルートの場合:**
    *   **⏪ 遡り学習**: つまずきを解消するための前提知識ノード。（※UIの次点リストでは生徒の混乱を防ぐため「再構成知識」「視点」を除外し、純粋な知識とタスクのみを提示）
    *   **⏩ 横展開**: 同じ親概念に属する兄弟ノード。
    *   **⏭️ 応用先**: 現在の概念を前提知識として利用する、次のステップのノード。
*   **問題ルートの場合 (GNN-KT特化ツリー):**
    *   本命の問題自身を「📍現在地」として中心に据え、そこから「⬛ 測られるタスク（技能）」と「🟦 必要な知識」へ向かって放射状にエッジが伸びるインタラクティブなツリーを展開します。
    *   トリガーとなった再構成知識をハイライトし、周辺情報（親概念など）のエッジをトーンダウン（薄い青色）させることで、クリティカルパスを視覚的に強調します。

### 🚀 5. オントロジーに連動したスマート・ルーティング
バックエンドにおける「大問（モデリング）」と「確認問題（アセスメント）」の分離オントロジーをUIに直接マッピングし、ユーザーの検索意図に応じた最適な学習ルートを動的に構築します。ルート構築の際は「レゴブロック」のように各要素を再配置し、ノイズとなる応用問題は厳格に排除します。

*   **📘 概念インプット優先ルート (Concept Intent)**
    「〜とは何か」「〜の概念を教えて」というクエリに対して展開されます。
    1.  **第一アクション (インプット)**: 概念をゼロから解説する純粋な解説動画。
    2.  **第二アクション (モデリング)**: その概念が実際に使われる「大問」の実物とその解説動画。
    3.  **第三アクション (アセスメント)**: 理解度を試す「確認問題」の提示。
    4.  **【概念ルートの純化（ノイズ排除）】**: ヒットした概念が「タスク」だった場合、他のタスク（応用要素）が混ざった問題をモデリングやアセスメントの候補から完全に排除（※再構成知識からプロモートされたタスクは例外）。純粋な基礎問題だけに集中できるUXを実現します。

*   **📗 問題・解法ステップ優先ルート (Problem Intent)**
    具体的な数式画像や「〜の解き方」というクエリに対して展開されます。
    1.  **AI事前解説 (チャットUI)**: HyDEで生成されたアプローチ解説をAIチューターからのメッセージとして提示。
    2.  **本命問題の特定 (2段階ソート＆純化)**: ヒットしたタスク傘下の確認問題をベクトルソートで特定。この際、他タスクが混入している応用問題は排除し、純粋な問題を本命として提示します。
    3.  **第一アクション (解法モデリング)**: 抽出されたタスクを測る「大問（モデリング）」の実物とその解説動画を表示。
    4.  **第二アクション (概念インプット講義)**: 問題の解法を見た後に、そもそもそのタスクをどう行うかの「概念インプット解説動画」を復習として提示。
    5.  **次点 (前提確認のアセスメント/GNNトラバーサル)**: 曖昧な類似問題検索を廃止し、本命タスクの「入ってくる矢印（前提概念）」をGNNから逆引き。その真の前提を測る確認問題だけを抽出します。
    6.  **【次点問題の超・厳格フィルター】**: 前提問題を引き当てる際、「再構成知識が前提に含まれる問題」や「複数タスクが混在する問題」を徹底排除し、さらに「画面に出現済みの問題」も重複排除することで、完璧に純化された遡り学習を実現します。

### 6. Explainable AI (XAI) と表示の最適化
UI上で学習者に動画をサジェストする際、単に「板書に書かれている数式の羅列（`blackboard_ocr`）」を見せるのではなく、**「先生がどういう意図でその解説を行っているか（`explanation_summary`）」**を前面に表示する設計としています。また、動画の役割に応じて「💡 【メイン解説】」「⏪ 【前提・復習】」のバッジを付与し、生徒が「なぜこの動画を見るべきなのか」を納得して学習できる UX を実現しています。
さらに、AIが提示した問題の直下には「解答」と「解説」をスマートに分割するアコーディオンを配置し、自律的な自己解決サイクルを促します。
