# 🔍 AIチューター検索エンジンの仕組み (`app.py`)

本ドキュメントでは、フロントエンドアプリ（`app.py`）で採用されている検索アルゴリズム、ハイブリッド検索、スコアリング、およびGraph RAGを用いたネットワーク探索の仕組みについて解説します。

---

## 🛠️ 検索アルゴリズムの処理フロー

入力された自然言語（会話文）や画像から、意味的ドリフト（ノイズによる誤検索）を防ぎ、意図した概念・問題を確実にヒットさせ、さらにオントロジーの繋がりまで提示するパイプラインです。

```text
[ ユーザー入力 (自然言語 / ノート・プリント画像) ]
                        │
                        ▼
┌───────────────────────────────────────────────┐
│ 1. クエリの高速サニタイズ (ゼロ・レイテンシ)  │
│    正規表現で数式(LaTeX)や小問番号(1)等を除去 │
└───────────────────────┬───────────────────────┘
                        │
                        ▼
┌───────────────────────────────────────────────┐
│ 2. ベクトル類似度計算 (Dense Search)          │
│    `text-embedding-004` 等によるコサイン類似度算出  │
└───────────────────────┬───────────────────────┘
                        │
                        ▼
┌───────────────────────────────────────────────┐
│ 3. 意図判定によるベースライン微調整           │
│    「指導」「意味」等 ➔ 概念ノードのスコア底上げ│
│    「解き方」「演習」等 ➔ 問題ノードのスコア底上げ│
└───────────────────────┬───────────────────────┘
                        │
                        ▼
┌───────────────────────────────────────────────┐
│ 4. クエリ前処理 & キーワード完全一致ブースト  │
│    不要語（Stop Words）を除去しキーワード抽出 │
│    概念・問題テキストへのヒットで一重加点     │
└───────────────────────┬───────────────────────┘
                        │
                        ▼
┌───────────────────────────────────────────────┐
│ 5. カリキュラム時系列ペナルティ               │
│    トップヒットより未来（未習範囲）のノードを減点│
└───────────────────────┬───────────────────────┘
                        │
                        ▼
┌───────────────────────────────────────────────┐
│ 6. Graph RAG (オントロジー探索・ネットワーク構築) │
│    ヒットした概念・問題を起点に繋がりを取得   │
```

## 🌟 主な機能と特徴

### 1. ゼロ・レイテンシのクエリサニタイズ (ノイズ除去)
画像検索から抽出されたテキストに含まれる小問番号（例: `(1)`, `[ア]`）や数式（LaTeXの `$...$`）を、API通信（LLM）を挟まずに正規表現で瞬時に除去します。これにより、記号がキーワードとして認識されるのを防ぎ、「関係のない問題が完全一致ブーストを受けて検索トップに躍り出る」という誤爆を完全に防止します。

### 2. 意図判定 ＋ 不要語除去のハイブリッド検索
ユーザーの入力フレーズ（例: 「教えて」「とは」 vs 「問題」「解き方」）を検知し、概念ルートと問題ルートのベーススコアを動的に加点調整します。また、会話ノイズを除去してコアキーワードを抽出し、ターゲットのテキストに完全一致した場合に最大 `+30.0%` のブーストを加算します。重複ヒットによるスコア崩壊を防ぐため、1ノードにつき一重加点のみに制限しています。

### 3. 多段・配列引き当てロジック (Array Ready対応)
検索によってトップヒットした概念やタスクが、そのまま問題の引き当て条件となります。
従来のように「1つの問題＝1つの代表概念」という紐付けではなく、問題データが保持する**「タスク配列（`linked_task_names`）」と「知識配列（`linked_knowledge_names`）」の包含関係をチェックするロジック**を採用しています。これにより、検索結果が抽象的な知識ノードであっても、具体的なタスク（技能）ノードであっても、確実に大問・確認問題を引き当てることができます。

### 4. Graph RAG による多次元学習ネットワークの構築
トップヒットした概念や問題を中心に、ベクトル検索だけでは拾いきれない**「文脈の繋がり」**を提示します。

*   **概念ルートの場合:**
    *   **⏪ 遡り学習**: つまずきを解消するための前提知識ノード。
    *   **⏩ 横展開**: 同じ親概念に属する兄弟ノード。
    *   **⏭️ 応用先**: 現在の概念を前提知識として利用する、次のステップのノード。
*   **問題ルートの場合 (GNN-KT特化ツリー):**
    *   本命の問題自身を「📍現在地」として中心に据え、そこから「⬛ 測られるタスク（技能）」と「🟦 必要な知識」へ放射状にエッジが伸びるインタラクティブなツリーを展開し、GNN-KTの推論構造をそのまま可視化します。

### 🚀 5. オントロジーに連動したスマート・ルーティング
バックエンドにおける「大問（モデリング）」と「確認問題（アセスメント）」の分離オントロジーをUIに直接マッピングし、ユーザーの検索意図に応じた最適な学習ルートを動的に構築します。

*   **📘 概念インプット優先ルート (Concept Intent)**
    「〜とは何か」「〜の概念を教えて」というクエリに対して展開されます。
    1.  **第一アクション (インプット)**: 概念をゼロから解説する純粋な解説動画。
    2.  **第二アクション (モデリング)**: 多段引き当てにより抽出された、その概念が実際に使われる「大問」の実物とその解説動画。
    3.  **第三アクション (アセスメント)**: 理解度を試す「確認問題」の提示。

*   **📗 問題・解法ステップ優先ルート (Problem Intent)**
    具体的な数式画像や「〜の解き方」というクエリに対して展開されます。
    1.  **ゼロアクション (前提確認)**: いきなり答えを教えるのではなく、その問題を解くための基礎知識や視点（Graph RAGによる前提）を先に提示。
    2.  **第一アクション (解法モデリング)**: 本命の問題文と、その問題を直接解説している先生の動画をマージしてシームレスに表示。
    3.  **第二アクション (同タスクの横展開)**: タスク配列（`linked_task_names`）を比較し、**「同じタスク（技能）を測る別の問題」を優先して真の類題としてサジェスト**。

### 6. Explainable AI (XAI) と表示の最適化
UI上で学習者に動画をサジェストする際、単に「板書に書かれている数式の羅列（`blackboard_ocr`）」を見せるのではなく、**「先生がどういう意図でその解説を行っているか（`explanation_summary`）」**を前面に表示する設計としています。また、動画の役割に応じて「💡 【メイン解説】」「⏪ 【前提・復習】」のバッジを付与し、生徒が「なぜこの動画を見るべきなのか」を納得して学習できる UX を実現しています。
